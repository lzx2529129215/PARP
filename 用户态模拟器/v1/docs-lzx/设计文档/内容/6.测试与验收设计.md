
第一版的目标不是测试真实 Linux 页面回收，而是证明：
> **Shadow per-cgroup LRU、页面生命周期、扫描压力、隔离—执行—回滚链路在所有输入下保持正确。**

## 1. 测试分层
```text
CTest
├── 单元测试
├── 组件测试
├── 事件场景测试
├── 故障注入测试
└── 长序列一致性测试
```

### 单元测试
分别测试独立模块：
```text
list
hash table
allocator_ops
page/domain生命周期
LRU移动
swappiness预算
priority扫描量
结果统计
```
例如链表测试：
```text
加入 P1、P2、P3
→ 删除 P2
→ 验证顺序为 P1、P3
→ 验证节点不能重复挂链
```

### 组件测试
验证多个模块协同：
```text
PAGE_ADD
→ 哈希表插入
→ 加入inactive LRU
→ 更新domain统计
→ validate通过
```
以及：
```text
隔离
→ 模拟BUSY
→ putback
→ 状态和统计恢复
```

### 文本场景测试
用 `.trace` 文件描述完整场景：
```text
GROUP_CREATE 1
PAGE_ADD 1001 1 FILE 0
PAGE_ADD 1002 1 FILE 0
PAGE_ACCESS 1002 1
AGE_GROUP 1
RECLAIM_GROUP 1 1
ASSERT_PAGE_MISSING 1001
ASSERT_PAGE_LRU 1002 ACTIVE_FILE
```
场景解析器和C测试调用同一套公开API，避免出现两套行为。

## 2. 第一版必须覆盖的场景

### 页面基础生命周期
```text
创建cgroup
→ 加页
→ 访问
→ 老化
→ 隔离
→ 成功回收
```

### 四条LRU转换
分别验证：
```text
inactive_anon ↔ active_anon
inactive_file ↔ active_file
```
以及anon页不能进入file链。

### F1记账归属
```text
WPS创建页面
→ QQ访问
→ shared=true
→ 页面仍位于WPS的LRU
```

### 单cgroup隔离
```text
RECLAIM_GROUP 1
```
不得修改其他cgroup的页面和统计。

### 全局priority回收
验证：
```text
priority逐级降低
扫描量逐步增加
达到目标后立即停止
```

### swappiness
验证：
```text
swap_enabled=false
→ 不扫描anon

swappiness=0
→ file优先

swappiness=200
→ anon优先
```

### 大folio
```text
order=9
→ 统计为512个基础页
→ 不拆分
→ 允许overshoot
```

### 模拟失败
分别注入：
```text
BUSY
DIRTY
WRITEBACK
PUTBACK
ACTIVATE
UNEVICTABLE
```
检查页面最终位置和批次统计。

### 无进展退出
所有候选都返回 `BUSY`：
```text
不得无限循环
→ 最终stop_reason = NO_PROGRESS
```

### 分配失败
自定义测试分配器在第N次申请时返回 `NULL`，验证：
```text
当前事件失败
→ 之前状态保持完整
→ validate仍通过
```

## 3. 一致性检查测试
还要故意构造内部损坏，确认验证器能发现：
```text
同一页面重复挂链
统计页数被篡改
ISOLATED页面仍在LRU
charge cgroup与所在domain不一致
页面类型与LRU类型不一致
```
这些测试可以使用仅在测试目标中开放的内部辅助接口，不暴露给正式公共API。

---

## 4. 确定性要求

第一版不允许测试结果依赖：
- 系统时间；
- 线程调度；
- 随机哈希种子；
- 哈希表遍历顺序；
- 指针地址。

统一使用：
```text
event_seq作为逻辑时间
cgroup_id作为稳定排序依据
LRU头尾定义固定
余数按cgroup_id分配
```
同一个trace运行多次，输出必须逐字一致。

## 5. 编译检查
CMake提供以下配置：
```bash
cmake -S . -B build \
  -DCMAKE_BUILD_TYPE=Debug \
  -DRECLAIM_ENABLE_TESTS=ON \
  -DRECLAIM_ENABLE_SANITIZERS=ON
```
Debug测试启用：
```text
-Wall
-Wextra
-Wpedantic
-Werror
AddressSanitizer
UndefinedBehaviorSanitizer
```
并运行：
```bash
cmake --build build
ctest --test-dir build --output-on-failure
```
后续再增加 ThreadSanitizer，用于多线程版本；第一版单线程不启用。

## 6. 第一版验收标准
必须同时满足：
```text
所有CTest通过
编译无warning
ASan无越界、use-after-free和内存泄漏
UBSan无未定义行为
所有场景结束后validate通过
同一trace重复运行输出一致
错误路径不留下ISOLATED页面
引擎销毁后分配计数归零
```

建议测试目录初步组织为：
```text
tests/
├── unit/
├── integration/
├── scenarios/
│   ├── basic_lifecycle.trace
│   ├── cross_cgroup_access.trace
│   ├── priority_reclaim.trace
│   ├── swappiness.trace
│   ├── executor_failures.trace
│   └── large_folio.trace
└── test_support/
```
