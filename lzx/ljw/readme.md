2.关于实验的设计，要涉及多个使用场景，多个app的切换，然后需要让后台app真正有无关的内存占用，然后我们移出这一部分，将多出来的内存留给前台app和即将要重入/打开的app

具体方案可以把交接文档发给gpt，然后根据gpt的反馈进行设计

主要目标：让上层用户信息下沉到内核，指导内存回收，降低direct reclaim ， refault 和 OOM 的次数

场景：
随着 PC 应用规模和端侧人工智能任务的内存需求持续增长，
多应用并发场景中的瞬时内存峰值更加频繁。Linux 主要依据
历史访问信息选择回收页面，难以识别即将再次访问的文件页和
即将变冷的匿名页。错误回收会引发 refault、交换 I/O 和
direct reclaim，造成前台应用卡顿甚至后台应用被OOM杀死
