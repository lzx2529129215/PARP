# 运行与验证

## 离线阅读和复算

在包的根目录执行，不需要虚拟机、sudo 或运行原生应用：

```text
python -X utf8 -B tools/verify_bundle.py
python -X utf8 -B tools/summarize_results.py
```

完整性校验检查包内 SHA-256、已冻结运行源码、资格记录引用的原始文件，以及任务通道引用的历史源码。汇总命令只更新 `summaries/`。

## 本地功能检查

进入 `workspace/parp-userspace-deficitfix-20261117`：

```text
python -X utf8 -B -m unittest discover -s controller -p "test_*.py"
python -X utf8 -B -m unittest discover -s tests -p "test_*.py"
python -X utf8 -B run_total.py --check --scope per_app
```

整理后验证结果记录在根目录 `validation.json`。功能测试与源文件核验不代表实机收益达标。

## 新实验先建新目录

本包主代码的 `results/` 已有真实数据，运行入口会拒绝覆盖它。不要删除旧结果来重跑。

在包根目录执行，例如：

```text
python -X utf8 -B tools/prepare_fresh_run.py --name parp-new-run-20261118
```

工具只复制本版代码和必要配置到 `workspace/parp-new-run-20261118`，创建空 results，不自动启动实验。已有同名目录会被拒绝。日期只是命名示例。

## 现有 Ubuntu 虚拟机中手工运行

前提见 [环境与依赖](03_环境与依赖.md)。保持 `workspace/` 内各兄弟目录的相对关系。以下 `<新实验目录>` 均指刚创建的目录，不是本包有结果的归档目录。

### A. Windows 宿主机终端：内存采样

进入宿主机上的 `<新实验目录>`，执行并保持终端打开：

```text
python -X utf8 -u -B lab/host_watch.py
```

这是 Windows 专用采样，原有启动门槛为可用内存至少约 3 GiB；新鲜度等检查由 `lab/suite.py::host_gate` 执行。不要伪造采样值或降低门槛绕过检查。

### B. Ubuntu 普通用户终端：准备并启动采集

进入虚拟机可见的同一 `<新实验目录>`：

```text
python3 -B run_total.py --check --scope per_app
python3 -B prepare_guest.py
sudo python3 -u -B "$HOME/$(basename "$PWD")/root_guard.py" --minutes 120
```

仅最后一个命令需要在本地输入 sudo 密码。保持终端打开。辅助程序仅管理明确绑定的四应用测试 cgroup，结束时恢复原 zswap 状态。

### C. Ubuntu 另一个普通用户终端：实际实验

进入相同 `<新实验目录>`，固定为本批相同测试上限：

```text
python3 -u -B run_total.py --scenario revisit --scope per_app --limit-mib 3854 --reference-limit-mib 6144 --target-gap-mib 256 --minimum-gap-mib 64
```

程序先采一条新的独立需求参考，要求没有 high/max/OOM 事件；然后在同一 3854 MiB 上限下执行关闭 3 轮、开启校准 3 轮，缺页校准通过后才执行正式开启 3 轮。

这复现的是本批协议和限额，不保证不同启动状态会得到相同毫秒数或相同缺口。每轮启动时仍要求至少 64 MiB 缺口，未通过会在负载开始前拦截并保存记录。

若要按“参考峰值减去目标缺口”自动确定新上限，可以省略 `--limit-mib 3854`；这种运行可能选出不同上限，应作为新条件单独比较，不能与本批均值混在一起。

### 实验中观察什么

- `DEFICIT_ADMITTED`：实际启动缺口及准入是否通过。
- `PEAK_SPACE_CHECK`：主峰开始前仍差多少；关闭组有缺口是对照现象，开启组有缺口是目标未达到。
- `RUNTIME_TARGET_UNFILLED`：某个预测增长段截止时仍未补足。
- `RUNTIME_ALERT`：调用越界等事件，必须检查是否影响当前轮次。
- `PROTECTION_EVENT`：回收控制暂停/退出，原生任务继续测量。
- `FAILED` 或 RUN 状态 STOPPED：批次中止，后续不再自动加压。

不要只等进程退出码；要同时看主峰空间、较早截止、保护事件和响应代价。异常记录不能悄悄删除或通过改阈值混入旧批次。

### 结束和恢复

程序 finally 会通知辅助程序恢复，结果中保存 `RESTORE-revisit.json`。核对 zswap、实验 cgroup 清理情况，以及完整的 trial cleanup 字段。

宿主机采样需要结束时，在其新实验目录的 PowerShell 执行：

```powershell
New-Item -ItemType File -Path .\lab\HOST_STOP -Force
```

本包也保留了用于临时共享文件任务通道的 `start_vm_experiment.sh`、`restart_vm_collector.sh` 和 `guest_session.py`。手工按 A/B/C 运行不需要启动这个任务通道；没有设置网络监听或开机服务。
