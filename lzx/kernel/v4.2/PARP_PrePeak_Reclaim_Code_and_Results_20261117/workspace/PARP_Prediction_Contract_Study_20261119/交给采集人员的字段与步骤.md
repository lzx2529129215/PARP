# 按最终输出反推的采集规格

本轮确定了理想输出接口和可复查的控制器效果；没有确定最优历史长度或证明最少输入。采集原始序列，后续在同一批数据上比较 2/4/8/16 秒历史；不要让采集人员凭经验选一个历史长度。

## A：需求、WSS、缺页预测需要的数据

低成本计数器每 100 ms 记录；WSS/访问观测每 500 ms。每条记录有 run_id、app_id、PID集合、进程启动时间、单调时钟、读取起止与有效标记。采集在受测应用 cgroup 外运行，单独记录采集 CPU/墙钟。

| 字段 | 如何获得 | 已有/缺失 |
|---|---|---|
| RSS | 同一应用进程口径的 `/proc/PID/status` VmRSS；记录PID集合，避免换PID后直接作差 | 原数据有 RSS；需要补更长、同运行同步日志。多进程 RSS 可能重复共享映射，不能当独占占用 |
| memory.current | 对应应用 cgroup 文件，字节；100 ms原值，保存每500 ms末值 | 旧预测数据没有同一次运行的该字段；现有回收实验日志有，可复用读取程序，不能从另一运行拼字段 |
| 累计缺页、主缺页 | `/proc/PID/stat` minflt/majflt，或一致的 cgroup memory.stat 口径；按实际500 ms边界取差 | 原数据有窗口缺页；新采累计原值并注明口径，重启/计数重置标无效 |
| WSS | 现有 Referenced 代理采法：开始清受测应用访问标记，窗口后读 smaps_rollup Referenced；保存真实暴露/扫描/读完时间 | 0.5秒数据已有；同一套固定负载10次、每次12秒，需补长记录。WSS不等于RSS |
| anon/file、refault、PSI、CPU使用 | memory.stat、memory.pressure、cpu.stat 原始计数及实际时间 | 系统可读；先记录供增删特征和异常解释，不默认全部作为模型输入 |
| 干预上下文 | high/max/min/low、memory.events、swap、所有回收调用起止/请求/实际占用变化、前后台和上游预测结果 | 系统/控制器已有来源，需要同步导出；上游未来真值只作标签，不伪装成真实预测输入 |

初始需求模型候选仍可用“过去的 WSS、RSS、memory.current、窗口缺页”作为基础，再比较加入 CPU、组成、重访是否有收益。输入向量中不放操作名、序列编号、窗口编号或距脚本峰值时间。

## A 的未来答案怎么从记录生成

对每个有效时刻 t：只取 t 以前且已读完的数据作输入。

- 后续40个500 ms窗口的 WSS，是 WSS 目标；各窗口缺页增量是缺页目标。
- 后续各窗口末 `memory.current - t时刻memory.current` 是占用增量目标，可为负。
- 同时保留100 ms原值及每段最大值，检查短峰是否被段末值漏掉。当前已验证接口分辨率为0.5秒，不声称覆盖所有更短的瞬时峰。
- 标签参考中本服务不主动回收，并确认没有 high/max/OOM 限制需求；受限制/回收后的占用不直接当完整需求答案。
- 不能把未来缺页数乘4096当占用增量，不能把5秒WSS插成0.5秒，也不能把缺失值补成实测0。

固定 high 的参考仍须保留**完整序列**的 WSS/占用峰值和对应保留量；它与仅有未来20秒的滚动标签分开归档。

## B：要训练真实“安全冷量”，还缺访问/重访记录

仅靠 WSS/RSS/缺页总数不能知道接下来会重访哪些旧页。这部分既有数据没有，不能声称四个总量足以训练完整冷热能力。当前理想实验用整应用冷热真值；本阶段若继续只训练需求分支，B可由负责冷热模块的人员补采接入。

已只读核对当前虚拟机：Linux 6.17.13，`CONFIG_IDLE_PAGE_TRACKING=y`，`/sys/kernel/mm/page_idle/bitmap` 存在，但普通qi用户不能读写；`CONFIG_DAMON` 未启用，不能直接让采集人员运行DAMON。原始核对在 `results/INPUT_AVAILABILITY.json`。

可采用当前内核已有的 Page Idle 接口开发访问日志，采集进程需本地相应权限。本轮没有实现或启动这个页采集器；下列是需交付的具体记录与步骤：

1. 用受测进程 maps/pagemap 建立当前驻留页身份，关联 app_id、PID启动时间、映射代次、地址/偏移、PFN和页大小；同应用共享页去重，并核对计费归属。pagemap文件“可读”不代表普通用户可得到PFN。
2. 每500 ms先记录上一段 idle bitmap，再只为受测应用的合格页重新设置 idle 标记。保存本段哪些页被访问、哪些仍驻留、哪些身份变化/不可确认；不要只留下访问总数。
3. 大页按head页与kpageflags正确计数；非LRU、锁定、迁移、映射变化、未完整观测的页不能直接当作已确认冷页。保留有效掩码。
4. 对 t 时刻的有效驻留页，检查后续40段访问记录的并集：其中未来20秒未被观察到访问、且身份/观测有效的字节，形成保守冷量标签。未来记录不满20秒时标缺失；不能把“未记录到”当“永不重访”。
5. 每500 ms会重新标记，因此标签要合并后续40段记录，不能只读取第20秒那一张位图。每段访问位图与驻留位图采用二进制保存，页身份表按变化保存，避免逐页大JSON。
6. 若用Page Idle推导WSS，与Referenced清访问标记法不要并行混用同一批页。注明 `wss_source`，分开验证口径与开销，不能无说明混合旧数据训练。

采样未观察访问只是冷量标签的证据，不是任意页都能无损回收的保证；最终还受真实释放校准、保护设置、预算和实时refault/PSI限制。当前回收器操作粒度仍是应用cgroup，本批不证明能够定向挑选应用内页面。

接口依据：[Linux Idle Page Tracking](https://docs.kernel.org/admin-guide/mm/idle_page_tracking.html)、[Linux pagemap](https://docs.kernel.org/admin-guide/mm/pagemap.html)。

## 哪些旧数据继续用

- `predictor-handoff-20261106/predictor/data/GIMP_30序列_启动分项补充版.xlsx`：与原manifest哈希一致，记录192条实测、768条模拟；实测可作操作级基线，不能把模拟计作实测。
- `predictor-handoff-20261106/predictor/lookup_predictor/gimp_5s.csv`：43次PASS实测、384行可作当前口径基线，支持粗粒度远期预测；不提供0.5秒真值或同运行memory.current。
- 旧0.5秒采集：10次、240窗口，每次12秒；可保留短期细粒度基线，不能生成完整20秒未来目标。
- 旧回收日志可复用读取代码、校准和故障分析；不能横向拼成上述同一次用户操作的缺失字段。

## 最小补采安排

先3次预采，只有时间对齐、开销、访问有效性、需求未被压限均合格后再扩大。每次120秒：前20秒积累历史、中间70秒使用已有操作序列、后30秒保留未来标签。保持原始时间，超时/失败窗口标无效，不修改名义时长掩盖。

初始选已有目录中5套序列、每套6次，共30次，净记录60分钟，另计启动/恢复/人工操作；改变等待时间和文档规模，不固定“第几秒必有峰值”。每套4次训练、1次验证、1次最终测试，整次运行不跨集合。这个划分仅验证已有序列上的变化，不等于未知新操作泛化。

完成后再比较历史长度与输入组；采集规格不宣称“8秒历史”已经最优。冷热采集程序/真实模型尚未接入的部分，继续保留明确的理想占位输出。
