# 本次选用的预测输出与代码改动

本轮先验证输出，不训练模型。候选输出在 10 种理想形态、12/20/30 秒范围中筛查；原生虚拟机运行和边界见 `实验结果.md`。当前选择是在本批候选和场景中的工程选择，不是任意应用上的全局最优。

## 最终输出：缺页保留

每次调用时间为 t，默认 H=20 秒、分段 0.5 秒，返回 40 个未来窗口；每 0.5 秒更新。t=10 时返回 10～30 秒，t=20 时返回 20～40 秒，不再固定返回实验 0～25 秒。

| 字段 | 精确定义 | 谁用它 |
|---|---|---|
| issued_s / horizon_s / step_s | 统一单调时钟的本轮时刻、未来范围、分段长度 | 校验所有应用和上游应用间输出是否对齐 |
| expires_s | 本轮结果的新鲜度截止；本实验 t+1 秒，与 H 不是一回事 | 过期后不授权继续回收 |
| 每段 wss_bytes | 该未来段的工作集估计，字节；真实采集必须注明观测口径 | 保护/保留需求、后续 WSS 预测训练 |
| 每段 occupancy_delta_bytes | 该段末相对本轮时刻的占用变化；可为负数，表示自释放；不计本服务将来主动回收的影响 | 合并各应用同一时间的需求，计算缺口 |
| 每段 pgfault | 该未来段 `(start_s,end_s]` 内缺页次数，非从 t 开始的累计值 | 按用户要求保留的辅助预测和分析；不乘页大小当新增需求 |
| reclaimable_bytes | 当前仍可提供的额外安全冷量；不是每次调用新发一份预算 | 限制捐赠量 |
| safe_until_s | 冷量保证有效到的时刻 | 拦住即将重访的捐赠；本批候选对 H 内会重访的整应用直接给 0 冷量 |

未来真实函数和脚本函数共同遵循 `OUTPUT_CONTRACT.json`、`PredictionRequest`、`validate_output()`。脚本的私有 Scenario 提供正确答案；它不代表已用历史输入学会预测。历史长度不可能由这种 oracle 证明最优。

示例：t=10，某应用当前 16 MiB，预计 t=20 增至 272 MiB，则后续对应点的占用增量为 +256 MiB；只在发生首次申请的那个窗口给约 65536 次负载页缺页，后面不会每格重复这个计数。另一冷应用在 20 秒范围内将重访，则冷量给 0。

## 为什么保留这些量

- 只看 WSS：在“WSS变化小但占用增长”里漏回收，在“访问已有驻留页、WSS上涨但无新增占用”里可能误回收。占用增量单独输出，解除这个混淆。
- 有占用但没有安全冷量：可知道缺多少，却仍可能向即将重访的应用捐赠。冷量与有效期是独立约束。
- 缺页预测在这批逻辑筛查中未改变空间决策；按用户最新要求保留，与 WSS/占用逐段对齐，后续可再研究其用途。
- 缺口、回收开始时间、截止时间不是模型额外猜的字段，由控制器把预测与实时剩余空间、校准速度、预算合并计算。

12 秒范围实际补齐过缺口，但保守速度预算未通过；30 秒没有展示比 20 秒更多的本批覆盖收益，当前默认 20 秒。它依赖本批约 144 MiB 回收量及测得速度，不能覆盖任意缺口。范围保留为参数。

## high 与本轮结论的边界

固定 high 沿用独立的全序列参考包络/保留配置；两臂使用相同规则，原生事件中未通过低 high 制造回收。它由实验已知序列生成，不是本轮滚动 20 秒输出推出来的已训练能力。后续仍需要采完整参考序列的 WSS/占用峰值来配置或训练这部分；不能声称仅凭本批滚动接口已经解决未知全序列最大值。

## 保留原版后验证的回收改进

1. **新峰值身份。** 原版对滚动窗口重新编号后，下一峰仍可能叫“0”，导致旧峰结束后正常更新被拒绝。`scheduler_fix.py` 仅在旧保护结束后分配新代号；原有峰内截止和保护边界仍锁定。原版在反复波动筛查中复现异常，候选修正消除；原生反复波动复测通过。
2. **可行容量。** 调度估计使用当前安全冷量和剩余尝试预算，不再始终把最初校准容量当作仍可用容量。安全冷量不足时明确报告，未把未补齐记为成功。
3. **已实现增长扣除。** 实际申请可早于下一预测网格点。只按预测时钟扣除会把已申请的部分再次算成未来需求。`Pipeline.need()` 用当前实测占用变化，并扣除本服务已观察到的主动释放影响；旧的按时间算法保留为 `need_mode='time'` 对照。逻辑回归及阶跃、缓慢增长、V形、反复波动原生复测通过。

固定 high、0.5 秒更新、原计划身份/预算不重置、峰内截止锁定、refault/PSI保护均继续使用。`controller/` 15 个文件与 GitHub `01660b55f0f2f5af3109a49310bdbe4d2755f1fa` 一致；候选修正在外层适配/调度子类中，尚未上传 GitHub。

完整调用：`predict_inter_app()` → 各应用 `predict_intra_app()` → 对齐需求/冷量 → `ColdReply` 与保护分数适配 → `Coordinator` → `Executor` → 真正的 `memory.reclaim` → 实测反馈。原生测试和以后模型调用的输出格式一致。
