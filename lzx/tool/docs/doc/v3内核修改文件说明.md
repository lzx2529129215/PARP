# 二、功能分别位于哪里

## 1. 二级水位线

二级水位线不是简单写在 `vmscan.c` 中的一个阈值，而是一套跨页分配和 memcg 的独立机制，涉及以下 **7 个文件**：

```text
include/linux/memcontrol.h
include/linux/tier2_watermark.h
mm/Kconfig
mm/Makefile
mm/memcontrol.c
mm/page_alloc.c
mm/tier2_watermark.c
```

这说明它至少包含：

```text
配置开关
    ↓
头文件接口
    ↓
独立实现文件
    ↓
memcg 管理
    ↓
页分配路径触发
```

所以二级水位线功能不能仅通过迁移 `mm/vmscan.c` 获得。

---

## 2. MGLRU 与预测策略

以下功能集中在：

```text
mm/vmscan.c
```

包括：

* generation 调整；
* Markov pull 预测路径；
* `evict_folios()` 前的 cycle-level Markov prepare；
* LSTM next-use 应用状态；
* app current、app predict、app probability；
* app 与 cgroup 绑定；
* workload history；
* Markov transition；
* observe-only hint；
* debugfs parser；
* LSTM 概率驱动的 `nr_to_scan` 策略；
* scan budget 的 original/proposed/applied 统计；
* generation adjustment hook；
* 相关节流和统计字段。

当前没有发现独立的 anon/file 策略修改，因此目前是：

```text
Markov 已预留参与 anon/file 决策的能力
但尚未真正修改原始 anon/file 选择结果
```

# 三、所谓“eBPF Map”的准确性质

当前实现中**不存在标准 eBPF Map**。

没有发现：

```text
SEC(".maps")
BPF_MAP_TYPE_*
bpf_map_lookup_elem()
bpf_map_update_elem()
BPF loader
BPF skeleton
BPF kfunc
```

你当前的 next-use、Markov、history 等状态，实际上是：

> 定义在 `mm/vmscan.c` 中、由自旋锁保护的静态内核数组或状态表，并通过 debugfs 命令由用户态维护。

因此建议后续文档中不要再称其为“eBPF Map”，可以称为：

```text
内核预测状态表
内核策略映射表
debugfs-backed kernel state table
```

除非以后真正接入 BPF Map。

# 五、迁移到同版本内核时应该怎么做

对于完全相同的基线：

```text

mm/Makefile
```
