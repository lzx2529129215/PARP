# PARP effective-tier 改进报告（0809）

## 1. 实验目标

本轮实验基于 `myself-kswapd/lzx/kernel/v4-parp` 的 PARP/MGLRU 方案继续推进，目标与 `readme.md`、原 `交接文档.docx` 保持一致：

- 在 cgroup 内引入二级水位线，结合应用间预测结果与 memcg 剩余量，指导回收触发、观测和后续保护预算。
- 根据应用内页面模型的预测结果，在 MGLRU 原生 tier 保护门控处调整页面的 effective tier，而不是替换 MGLRU。
- 让上层用户/应用信息以弱先验形式下沉到内核，改善“该保护谁、该回收谁”的判断质量，目标是降低 direct reclaim、refault 和 OOM 风险。
- 保持安全边界：默认 predictor/sysctl 关闭，APPLY 路径未进入激进策略；在数据完整性、锁延迟、PSI/OOM 和回收效率门禁未通过前，不把性能收益写成已证明结论。

## 3. 本轮代码改进

### 3.1 effective-tier 数据完整性

- 文件：`tools/parp/effective_tier/collector.py`
- 改动：增加 session 级 trace loss before/after delta 采集和汇总，输出 `trace_loss_delta`、`trace_loss_delta_zero` 等字段。
- 作用：当 overrun/dropped delta 非零时，将数据标记为 incomplete，阻止后续训练、阈值选择或 APPLY 误用不完整数据。

### 3.2 offline 测试

- 文件：`tools/parp/effective_tier/tests/test_phase_e.py`
- 改动：补充 before/after delta、非零 trace loss 和不一致字段的单元测试。
- 验证：`python3 -m unittest discover -s tools/parp/effective_tier/tests -v`，结果 `Ran 105 tests`，`OK`。

### 3.3 trace_events 运行期告警修复

- 文件：`kernel/trace/trace_events.c`
- 改动：为 trace printk 参数 bitmap 检查增加有界处理，避免参数编号大于等于 64 时执行 `1ULL << arg`。
- 作用：修复 PARP 长 `TP_printk` 参数列表触发的 UBSAN `shift-out-of-bounds` 风险，保证 trace event 可读。

### 3.4 cgroup v1 tier2 接口补齐

- 文件：`mm/memcontrol-v1.c`
- 改动：在 `mem_cgroup_legacy_files[]` 中为 `CONFIG_PARP` 补齐 8 个 `tier2_*` cftype。
- 作用：Ubuntu cgroup v1 memory 挂载下可以看到并使用以下文件：
  - `memory.tier2_enabled`
  - `memory.tier2_alloc_scale`
  - `memory.tier2_demote_scale`
  - `memory.tier2_alloc_wmark`
  - `memory.tier2_demote_wmark`
  - `memory.tier2_headroom`
  - `memory.tier2_below`
  - `memory.tier2_stats`

## 7. 当前进展结论

本轮已经完成“内核可编译、可安装、可启动、运行态关键接口可见、trace 可读、cgroup v1 接口补齐、已知 PARP trace_events 告警修复”的目标。当前不能宣称的结论是：effective-tier 已经降低 refault/direct reclaim/OOM，或模型 APPLY 已可用于生产策略。原因是 P1R 小步回收实验、端到端 session 数据完整性和系统层效果评估仍未完成。

## 8. 后续方向

1. 完成 session exporter：每个 session 写入 `SESSION_BEGIN`、`SESSION_END`、trace per-cpu stats 的 before/after 和 delta。
2. 增加内核 debugfs 计数器：`tier_gate_seen`、`score_attempted`、四象限决策、bypass 原因，并与 trace 条数闭环。
3. 设计 P1R 轻度回收实验：使用小步 `memory.reclaim` 脉冲，例如 4 MiB -> 冷却 -> 8 MiB -> 冷却 -> 16 MiB，并以 PSI、回收进展和 no-progress 状态实时中止。
4. 建立压力感知门控：LOW / MODERATE / HIGH / CRITICAL 分级；高压削弱预测升级，CRITICAL 进入 strict Native fallback。
5. 数据完整后再训练：只有 `trace_loss_delta_zero=true`、tier gate coverage 完整、无 sequence gap、计数器对账通过时，才允许训练、阈值选择和 P2/P3。
6. APPLY 前置门槛：模型质量、锁延迟、scan/reclaim 效率、PSI/OOM 安全门全部通过后，先考虑 `APPLY_PROTECT_ONLY`，最后才考虑双向 APPLY。
7. 用户行为融合：窗口焦点、Z-order、遮挡、Tab 可见性等上层信息只作为 App/cgroup 保护预算的弱先验，不直接覆盖单页 tier。

## 9. 2026-08-10 新增要求补充

### 9.1 输入材料结论

本次新增要求来自 `新增要求` 目录中的 `page_alloc.md`、`vmscan.md`、`录音.txt` 和 `录音适配截图.png`。核心信息已经统一为一条主线：

- 水位线仍然负责触发回收，但不应独立承担完整策略。
- 真正需要调整的是 `mm/vmscan.c` 里的 MGLRU node 级回收链路，重点是 `shrink_many()` 及其相关 memcg/bin 选择。
- 应用间预测概率应该下沉到 memcg 回收顺序里，低概率 memcg 先回收，高概率 memcg 后回收。
- `page_alloc` 侧的 watermark 和 `kswapd` 仍然保留，属于触发入口，不是新策略主干。

### 9.2 这次实际改动
