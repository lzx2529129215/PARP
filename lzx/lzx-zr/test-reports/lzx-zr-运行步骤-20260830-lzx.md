# lzx-zr 运行步骤教程(照着做就能跑)

> 写于 2026-08-30。目标:零基础、一步步复现我跑测试的全过程。
> 本项目的代码在 **VM 上**跑,不在 Windows 本机跑。

---

## 0. 开始前,你只需要两样东西

1. **虚拟机连得上**(已经配好了,命令就是 `ssh ubuntu-vm`)
2. **VM 上有 Python 3**(已经装了,3.10.12,不需要 pip 装任何东西)

> 如果 `ssh ubuntu-vm` 报错,先看同目录的《SSH连接虚拟机指南.md》,或按下面「常见问题」处理。

---

## 第 1 步:连上虚拟机

在 Windows 上打开 **Git Bash**(或 CMD/PowerShell 都行),输入:

```bash
ssh ubuntu-vm
```

**预期看到什么**:提示符从 `C:\...` 变成 `zr@zr-virtual-machine:~$`,说明你已经进到 VM 里了。

> 下面所有命令,只要是在 VM 里跑的,我都用 `$` 开头;在 Windows 本机跑的,用 `>` 开头。

---

## 第 2 步:把代码传到虚拟机

代码在 Windows 本机的 `f:\huawei\git\PARP\lzx\lzx-zr`,VM 上还没有,要先传过去。

**先退出 VM**(在 VM 里输入 `exit` 回车),回到 Windows,然后执行:

```bash
> cd /f/huawei/git/PARP
> scp -r lzx/lzx-zr ubuntu-vm:~/lzx-zr
```

**预期看到什么**:一堆文件名滚过,最后没有报错就成功了。这条命令把整个 `lzx-zr` 文件夹复制到 VM 的家目录 `~/lzx-zr`。

> 如果代码改过了,重新跑一遍这条命令就能覆盖更新。

---

## 第 3 步:进到项目目录

```bash
> ssh ubuntu-vm          # 重新连上 VM
$ cd ~/lzx-zr            # 进到项目目录
$ ls                     # 看一眼
```

**预期看到什么**:列出 `configs`、`docs`、`kernel`、`predictor`、`runtime_monitor`、`tests`、`tools` 等目录。

---

## 第 4 步:跑单元测试(验证代码正确性)

```bash
$ python3 -m unittest discover -s tests -p "test_*.py" -v
```

**预期看到什么**:

```
test_missing_region_order_is_unknown ... ok
test_q15_is_bounded ................... ok
test_snapshot_is_shadow_only .......... ok
test_stale_or_unknown_snapshot_falls_back_to_native ... ok
test_state_machine_requires_dwell ..... ok

----------------------------------------------------------------------
Ran 5 tests in 0.004s

OK
```

**含义**:5 个测试全过(`OK`),说明代码逻辑正确。

---

## 第 5 步:跑完整流程(生成预测结果)

这一步才是「真正的运行」——喂入示例数据,产出一堆预测文件。

```bash
$ python3 tools/run_workload_aware.py \
    --input tests/fixtures/observations.jsonl \
    --output-dir outputs/my_run \
    --mode SHADOW
```

**预期看到什么**:命令跑完没有报错,然后检查输出目录:

```bash
$ ls outputs/my_run
```

应该看到 **4 个文件**:

```
features.jsonl           ← 每个窗口提取到的特征
predictions.jsonl        ← 每个窗口的预测快照
prediction_snapshot.json ← 最后一个窗口的预测(格式化)
parp_shadow_hint.json    ← 经过校验后的「影子提示」
```

---

## 第 6 步:看结果长什么样

```bash
$ cat outputs/my_run/parp_shadow_hint.json
```

**预期看到什么**:一个 JSON,里面有 `mode`、`protection_hint`、`reclaim_hint` 等字段。

> 想直接看预测结论,看 `predictions.jsonl` 里的 `current_workload.dominant`(当前是什么状态)和 `next_workload.dominant`(预测接下来是什么状态)。

---

## 第 7 步(可选):换参数再跑

有两个开关可以换:

**换模式**(`OBSERVE` 只观察 / `SHADOW` 影子提示):

```bash
$ python3 tools/run_workload_aware.py \
    --input tests/fixtures/observations.jsonl \
    --output-dir outputs/my_run_observe \
    --mode OBSERVE
```

**换预测方法**(`rule_trend` 规则趋势 / `second_order_markov` 二阶马尔可夫):

```bash
$ python3 tools/run_workload_aware.py \
    --input tests/fixtures/observations.jsonl \
    --output-dir outputs/my_run_markov \
    --mode SHADOW \
    --method second_order_markov
```

> 每次换 `--output-dir`,结果就存到不同的文件夹,不会互相覆盖。

## 常见问题

### Q1:`ssh ubuntu-vm` 报 `Permission denied`
→ 别用 `ssh zr@127.0.0.1` 这种直连,一定要用别名 `ubuntu-vm`(它会自动带上正确的密钥)。

### Q2:报 `Bad owner or permissions`
→ 在 Windows 的 CMD 里跑一句修复:
```cmd
icacls "%USERPROFILE%\.ssh" /reset /t
```

### Q3:`scp` 报找不到文件
→ 先 `cd /f/huawei/git/PARP`,确认当前目录下有 `lzx/lzx-zr` 这个文件夹(`ls lzx/lzx-zr` 能列出来)。

### Q4:跑测试报 `No module named ...`
→ 确认你在 `~/lzx-zr` 目录下(第 3 步的 `cd ~/lzx-zr` 没漏),命令里的 `tests`、`tools` 都是相对这个目录的。

### Q5:想看 `parp_shadow_hint.json` 里 `mode` 为什么是 `NATIVE` 而不是 `SHADOW`
→ 这是**正常现象**:示例数据用的是合成的旧时间戳(1970 年),被「TTL 新鲜度守卫」判定过期后自动回退到 NATIVE。逻辑是对的,不是 bug。详情见同目录的《lzx-zr-workload-aware-test-feedback-20260830-lzx.md》第 5.1 节。
