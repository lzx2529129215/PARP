# 更贴近实际的 Workload 场景设计说明

## 1. 设计目标

为了避免只用简单单窗口样本，本轮设计了连续 4 个观测窗口组成的场景，用于检验：

- 状态能否持续稳定
- 状态变化是否会被正确识别
- 预测是否只使用当前和过去信息
- 内存压力、冷态和访问模式能否区分
- 状态切换的 dwell 机制是否符合预期

场景数据仍然是用户态模拟数据，不代表某个具体应用的真实 trace。它们按照常见内存访问行为和监控计数器构造。

---

## 2. 场景列表

### 2.1 持续稳定热点

模拟一个反复访问少量热点区域的任务：

- region 重复出现
- 访问次数较高
- `hotspot_jaccard` 较高
- 工作集保持稳定
- PSI 和分配压力接近 0

期望状态：`STABLE_HOT`

可以检测系统是否会保护稳定热点，避免将其误识别成多热点或流式访问。

---

### 2.2 顺序流式读取

模拟文件扫描、连续数据处理或媒体流读取：

- region 按顺序前进
- 每个 region 访问次数接近 1
- 复用率低
- 工作集不会持续扩张

期望状态：`STREAMING`

可以检测系统是否能够区分顺序一次性访问和稳定重复热点。

---

### 2.3 突发工作集扩张

模拟应用启动、批量加载或短时间分配大量内存：

- `wss_delta_pages` 为正
- `allocation_delta_pages` 较高
- 缺页数量增加
- region 数量和工作集快速增加

期望状态：`BURST_EXPANSION`

可以检测系统是否能提前识别工作集扩张，从而为后续内存预算调整提供信号。

---

### 2.4 低价值冷态

模拟后台任务暂时没有访问，或者一组页面长时间不活跃：

- 工作集大小为 0
- 缺页、回收和 PSI 均为 0
- 前台标记可以为 1，但不代表内存压力

期望状态：`LOW_VALUE_COLD`

该场景专门验证 `foreground` 不会被错误当成内存压力。

---

### 2.5 多热点轮换

模拟数据库、多线程任务或多个活跃数据分区：

- 多个 region 有较高访问次数
- 热点数量较多
- 热点移动率较高
- 不能只保护单个区域

期望状态：`MULTI_HOTSPOT`

可以检测调度策略是否需要同时保护多个热点区域。

---

### 2.6 随机离散访问

模拟索引查找、哈希访问或低局部性访问：

- region 顺序不明显
- 访问次数低
- 空间局部性低
- 没有足够热点证据

期望状态：`UNKNOWN`

该场景遵守保守原则：证据不足时不强行判断成顺序、循环或热点模式。

---

### 2.7 内存压力场景

模拟系统出现内存压力的情况：

- PSI 升高
- 缺页增加
- 工作集仍然存在
- 访问行为和压力信号同时存在

期望状态：`MIXED`

可以检测系统是否会识别出压力状态，并在后续执行层采用保守策略。

---

### 2.8 扩张后进入稳定热点

模拟应用先快速加载数据，随后进入稳定计算阶段：

```text
BURST_EXPANSION -> BURST_EXPANSION -> STABLE_HOT -> STABLE_HOT
```

这个场景重点检测：

- 状态机是否需要连续窗口确认状态切换
- 扩张结束后是否能最终进入稳定热点
- Markov 是否能从已有转移历史中学习后续状态

---

## 3. 回测方式

回测代码位于：

- [tests/realistic_backtest.py](../tests/realistic_backtest.py)

每个窗口的处理顺序为：

```text
读取当前窗口
    ↓
提取特征
    ↓
更新状态机
    ↓
记录已经发生的状态转移
    ↓
预测下一个窗口
    ↓
和下一个窗口的期望状态比较
```

预测不会读取尚未发生的窗口状态，因此预测样本不包含未来信息。

本轮总计：

- 8 个场景
- 32 个观测窗口
- 24 个下一窗口预测样本

---

## 4. 评估指标

### 状态判断准确率

```text
正确识别的窗口数 / 全部窗口数
```

### 规则趋势预测准确率

```text
规则预测正确的下一窗口数量 / 全部预测样本数
```

### 二阶 Markov 预测准确率

```text
Markov 预测正确的下一窗口数量 / 全部预测样本数
```

这里的 Markov 预测使用已经记录的状态转移统计，不使用未来窗口数据。

## 6. 结果解读

### 状态判断

96.88% 说明当前规则对这 8 类构造场景的区分效果较好，尤其是：

- 稳定热点
- 流式访问
- 突发扩张
- 冷态
- 多热点
- 随机未知
- 内存压力

都能在连续窗口中保持较稳定的判断。

### 规则趋势预测

70.83% 说明简单规则能够覆盖多数稳定场景，但对“突发扩张持续多久、何时结束”的时间变化判断仍然有限。

### Markov 预测

91.67% 说明在已经积累状态转移历史后，Markov 预测对连续场景的表现更好。它比较适合用于有历史数据的在线策略输入。

## 7. 场景与调度策略的对应关系

| 场景 | 预测结果可提供的调度建议 |
|---|---|
| 持续稳定热点 | 保护热点页，减少热点回收 |
| 顺序流式读取 | 适度预取，降低旧页优先级 |
| 突发工作集扩张 | 提前准备内存，临时增加预算 |
| 低价值冷态 | 提高回收、压缩或迁移优先级 |
| 多热点轮换 | 同时保护多个活跃区域 |
| 随机离散访问 | 限制无效预取，优先保证容量 |
| 内存压力场景 | 使用保守策略，避免额外压力 |
| 扩张后稳定 | 先保障扩张，再转为热点保护 |

当前 lzx-zr 只输出预测和 shadow hint，不直接执行这些动作。

---

## 8. 限制和后续工作

这些场景是可解释的回测样本，不等同于线上真实准确率。后续接入真实 trace 后，还应继续评估：

- 不同应用和 cgroup 的差异
- 更长时间窗口
- trace 噪声和丢样本
- 状态切换延迟
- 预测置信度校准
- 调度动作执行后的收益和副作用

最终应同时关注准确率、误判代价和调度收益，而不能只看单一准确率数字。
