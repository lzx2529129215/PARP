# Workload 状态机与预测器调优迭代说明

## 1. 本轮目标

本轮目标是提升 lzx-zr 在更贴近实际的多窗口 workload 场景中的：

- 当前状态判断准确率
- 下一窗口预测准确率
- 状态转移统计的有效性
- 冷态、稳定热点、流式、突发扩张和内存压力场景的区分能力

本轮只修改 lzx-zr 目录内的代码和报告，不涉及仓库其他目录，也没有接入真实内核执行动作。

---

## 2. 发现的第一个问题：Markov 没有真正学习“下一状态”

原来的转移统计逻辑等价于：

```text
(previous, current) -> current
```

也就是每次记录状态时，把当前状态自己作为下一状态保存了。这会导致预测器看起来有 Markov 统计，但实际上更接近“原状态复制”，没有学习真正的状态变化。

### 调整方式

现在改为：

```text
current -> next_state
```

每次出现连续窗口时，使用前一个状态作为键，把当前状态计入它的后继统计：

```text
STABLE_HOT -> STABLE_HOT
BURST_EXPANSION -> BURST_EXPANSION
BURST_EXPANSION -> STABLE_HOT
```

预测时选择当前状态历史中出现频率最高的后继状态，并根据频次计算概率。

### 调整文件

- [predictor/workload_predictor.py](../predictor/workload_predictor.py)

### 调整收益

Markov 预测现在能够反映已经观测到的状态转移，而不是固定把当前状态当作下一状态。当前实现是轻量的“当前状态 -> 下一状态”一阶 Markov 基线；代码和历史输出中仍保留 `second_order_markov` 名称，后续如果需要真正的二阶模型，还应把最近两个状态作为条件并单独训练三元转移统计。

## 3. 发现的第二个问题：foreground 被错误当成内存压力

原来的冷态判断使用：

```text
sum(pressure.values()) == 0
```

但是 `foreground` 是任务是否处于前台的元数据，不是 PSI、缺页、回收或 swap 压力。如果 `foreground=1`，即使其他内存压力全为 0，状态也不会进入 COLD。

### 调整方式

现在计算内存压力时排除 `foreground`：

```text
pressure_load = sum(
    value for key, value in pressure.items()
    if key != "foreground"
)
```

只有真正的内存压力指标参与冷态判断。

### 调整文件

- [runtime_monitor/detector/state_machine.py](../runtime_monitor/detector/state_machine.py)

### 调整收益

低工作集、无缺页、无回收、无 PSI 压力的窗口可以正确识别为：

```text
LOW_VALUE_COLD
```

同时仍然保留原有约束：如果没有区域顺序且没有有效观测证据，仍然返回 `UNKNOWN`。

---

## 4. 保留的状态判定策略

本轮没有取消已有的保守回退机制，状态机仍然遵守以下原则：

- 没有区域顺序时，不推断顺序访问、循环访问或随机访问
- `UNKNOWN` 表示证据不足
- `MIXED` 表示压力或多个行为信号混合
- 状态切换需要满足 dwell window
- 状态切换后使用 cooldown，减少短时间抖动
- 预测过期或置信度不足时，后续执行层应使用 Native fallback

## 6. 回测方法

本轮不再只用单窗口判断，而是使用连续窗口：

- 8 个场景
- 每个场景 4 个观测窗口
- 总计 32 个状态判断样本
- 每个场景前 3 个窗口产生下一窗口预测
- 总计 24 个预测样本

预测严格按照时间顺序执行：

```text
处理当前窗口
    ↓
记录已经发生的状态转移
    ↓
预测下一个窗口
    ↓
使用下一个窗口的期望状态进行比较
```

这样可以避免直接读取未来状态后再预测，减少数据泄漏。

- 状态判断提升 12.50 个百分点
- 规则趋势预测提升 12.50 个百分点
- Markov 预测提升 12.50 个百分点

这些结果只代表当前构造的 8 类回测场景，不等同于真实线上 workload 的最终准确率。

## 8. 当前仍存在的限制

规则趋势预测目前仍然是轻量基线，对“突发扩张会持续几个窗口”与“扩张即将结束”这类时间长度判断还不够细。

因此本轮结果中：

- Markov 预测：91.67%，更适合已经积累转移历史的场景
- 规则趋势预测：70.83%，适合没有历史数据时快速给出保守趋势

后续如果接入真实数据，可以继续增加：

- 每种状态的持续时长
- 状态转移最短和最长持续窗口
- 预测置信度校准
- 不同 workload 的独立转移表
- 预测结果对回收、预取和内存预算的收益指标

---

## 9. 结论

本轮调优的核心不是增加复杂模型，而是修正了两个会直接扭曲结果的实现问题：

1. Markov 统计没有记录真正的后继状态
2. 前台标记被误计入内存压力

修正后，状态机能够更准确地区分冷态，预测器也开始使用真实状态转移信息。当前原型适合作为调度策略映射层的输入，但仍需要在真实 trace 和线上 workload 上继续验证。
