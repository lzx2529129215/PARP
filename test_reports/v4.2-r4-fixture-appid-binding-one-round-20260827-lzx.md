# v4.2-r4 fixture 同 App ID 绑定单轮验证报告

## 1. 实验目的

验证六个 GUI 应用 scope 与六个内存 fixture scope 绑定到相同 App ID 后，LSTM 应用间预测是否能够通过 `/dev/myfs` 覆盖 fixture 的主要工作集，并观察 effective-tier、bin-reclaim 与 Tier2 的机制动作和端到端指标。

## 2. 实验条件

- 内核：`6.17.13-parp-lzx-v4.2-apply-myfs-guided-r4 #22`
- 策略：Combined，`PARP=2`、`effective-tier=3`、`Tier2=1`
- 场景：peak/full，LSAPP held-out 序列，OOM-THRESHOLD 开启
- 随机种子：`20260826`
- 本轮有效结果：[summary.json](../test/outputs/parp_predictive_reclaim/peak-full-combined-20260827_173006-6.17.13-parp-lzx-v4.2-apply-myfs-guided-r4/summary.json)
- 对照有效结果：[summary.json](../test/outputs/parp_predictive_reclaim/peak-full-combined-20260826_191239-6.17.13-parp-lzx-v4.2-apply-myfs-guided-r4/summary.json)
- 两轮 `scenario-plan.json` SHA-256 均为 `699ce9296f3c1fae69e742b4a3da92a8056f25807cd9fdbca209a537ce6c6868`。

本轮 30/30 case 完成，6/6 GUI 窗口通过 X11 验证，自动化失败为 0，trace 丢失为 0，结果状态为 `VALID_DIAGNOSTIC`。由于仅有单轮且尚未与同环境 Native 成对运行，本报告用于机制诊断，不作为正式验收结论。

## 3. `/dev/myfs` 与 App ID 绑定证据

本轮常驻服务产生 60 次预测 ioctl，60 次均为 `APPLIED`，`ambiguous_domains=0`。在六个 GUI 与六个 fixture 都存活的主要测试阶段，46 次预测均携带 `nr_bindings=12`；其余较小绑定数出现在应用尚未全部启动或顺序关闭阶段。

这证明以下两类内存域已同时下沉到内核：

- GUI scope：`automation-<app>.scope`
- fixture scope：`automation-fixture-<app>.scope`

同一应用的两类 scope 使用相同 App ID，但 fixture 不参与 GUI 前台/生命周期事件判定。

绑定修复已经解决“fixture 大工作集没有应用身份”的问题。此前 effective-tier 和 bin 主要只能看到 GUI 小工作集；现在 262,124 个候选页获得应用上下文，且 bin 已实际移动 15 次。

但 effective-tier 仍只有 3 页实际保护、0 页降级。`hot-bias pages`/`cold-bias pages` 表示应用先验参与了评分，不等于最终动作。最终动作还要求页面模型分数跨过阈值、页面位于可调整的 native tier 边界、连续候选条件成立、非 severe-pressure 保护门控，并通过每批/每 epoch 的有界预算。因此绑定问题已经排除，下一瓶颈已转移到页模型、边界条件与动作预算。

## 6. 结论

1. **绑定修复有效。** `/dev/myfs` 已稳定携带 12 个绑定，fixture 页的应用上下文覆盖率从 0.063% 提升至 34.99%，bin 首次出现 15 次 rebin。
2. **当前最明确的收益仍是降低 direct scan。** 本轮 `pgscan_direct` 降低 36.74%，同时整体扫描效率提高 20.05 个百分点；Tier2 主动回收次数和页数接近翻倍，是这一变化的主要候选原因。
3. **还没有 pagefault/refault 与交互延迟收益。** pgfault 基本持平，但 file refault、major fault、启动 P95 和 CPU 时间均变差，不能用本轮宣称总体优化成功。
4. **机制冲突仍然存在。** Tier2 更积极地提前回收，降低了 direct scan，却可能增加后续复用页的 refault；effective-tier 虽已获得正确预测上下文，但只有 3 页实际保护，尚不足以抵消提前回收的副作用。
5. **单轮不足以区分真实效果与运行波动。** 下一步应在同一启动环境中使用相同场景计划连续运行 binding-OFF 与 binding-ON，至少 3 个相同 seed 成对比较，再决定是否调整 effective-tier 动作门控及 Tier2 回收强度。
